## CURRENT STATE / ARCHITECTURE / DECISIONS
- Previous Phase2 source registry distinguishes allow_fetch, allow_storage and allow_redistribution. However authenticated private BFF queries still required allow_redistribution, unnecessarily treating owner viewing as publication. All source rows except synthetic fixture are unverified by default; no external provider credentials or real Keycloak/mTLS deployed.
- New private BFF read switch: server env AUTOAXE_PRIVATE_EDUCATIONAL_MODE=true AND AUTOAXE_PRIVATE_EDUCATIONAL_OWNER_SUBJECT_REF exactly matching the authenticated OIDC subject; disabled unless explicitly configured. Official-event and market-series BFF allow approved personally stored source rows with allow_storage even when allow_redistribution=false, and still require valid owner session, scope, free_only, evidence, current approval. Flag alone does not bypass rights for another user. Public API and trade/ingest/collect permissions unchanged; public/service deployment must not enable the switch.
- PizzINT terms updated 2026-06-25 explicitly allow personal/educational access and public API endpoints with reasonable rate limiting, but forbid scraping beyond the provided API. The project already documented HTTP 200 JSON at https://www.pizzint.watch/api/dashboard-data on 2026-11-22; prior absolute broker denial mistakenly ignored this. Pin the scraper policy target to that API, provide JSON-only bounded TLS/IP-validated response helper and allow a broker job only after source registry approval. Continue blocking homepage HTML fallback. No real network-enabled worker or broker deployment introduced.
- BLS public data secondary-use terms include access date citation, attribution and disclaimer. DRAMeXchange grants non-transferable access, permits personal/noncommercial use, restricts distribution and also speculative prediction-market use. The noncommercial scope matters, but licenses are source-specific.
